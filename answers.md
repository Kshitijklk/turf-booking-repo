# E-O-D check

q1)  
When the customer sends the request, the requireAuth middleware runs first. It checks if the token
is present, verifies that it's a valid JWT, and if everything is correct, it stores the user's ID
and role in req.user. After that, the request goes to the requireRole("owner") middleware. This 
middleware checks req.user.role. Since the token belongs to a customer, the role is "customer"
instead of "owner" Because the role doesn't match, the request is rejected and the server returns 403 Forbidden

q2)
Logout removes the refresh token from the database. The access token still works for a little while 
because it can't be deleted by the server. But once it expires, the refresh token is gone, so the 
user can't get a new access token and has to log in again

q3)A phone number is predictable. Someone could easily guess numbers like 9876543210, hash them,
and compare them with the database. That's why we use HMAC, which adds a secret key. Without the
secret key, an attacker cannot generate the same hash
A refresh token is different. It is already a long, random value generated by the server. Nobod can
realistically guess it, Because the refresh token is already random and unguessable, using anormal
SHA-256 hash is enough. There is no need to add a secret key like HMAC.
